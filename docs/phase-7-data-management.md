# 第10步：本地备份、恢复与删除全部数据

## 使用流程

入口：“我的记录” → “数据与备份”。

- 导出：包含全部正式记录、书写草稿、心事整理草稿及它们引用的应用内照片。使用系统文件选择器指定保存位置，生成 `.zhiyu.json` 文件。备份未加密，界面明确提醒妥善保管。
- 限制：单个备份最多64MiB、单张照片最多30MiB；照片缺失或不可读、文件超限、写入失败均报错，不悄悄省略照片。已删除记录的内部恢复副本、旧迁移数据和随包音频不导出。
- 恢复：选文件 → 校验版本、结构、日期、照片路径和SHA-256 → 显示记录／照片数量、拟新增与保留数量 → 用户确认合并。
- 合并：新增不存在的记录id；已有同id记录保留本机版本。两类草稿各自只在本机没有该类草稿时恢复。重复导入不会重复新增正式记录。
- 照片：只接收 `photos/<字母数字横线>.image`，每份新增照片写入新路径。不同设备的同名照片不会覆盖。跨记录／草稿共享的照片只复制一份。
- 删除：输入“删除全部”后，再通过确认框确认。删除正式记录、草稿、应用内照片（含孤立照片）、旧 `entries/bottles/joys` 键、内部上一版副本。保留空的新版文档，避免下次启动重新迁移旧记录。
- 相册原图与用户已导出的备份属于外部文件，不删除。此操作是应用数据的逻辑删除，不声称对闪存执行不可恢复的物理擦除。

## 中断与失败保护

`DataMaintenance` 在记录Preferences内持久化 `maintenance_job_v1`，操作意图落盘后才开始更新数据。

恢复先校验并复制新照片，再保存操作意图。意图落盘前失败不会更改已有记录；可能产生的未引用照片由现有启动清理流程回收。意图落盘后采用继续完成策略，暂时关闭编辑入口，用户可重试，或由下次启动继续执行同一操作。

删除也先保存意图。正式数据、两类草稿和照片都清除成功后才移除意图。文件删除失败不会显示全部删除成功；下一次重试继续处理剩余数据。

启动顺序为：完成待处理操作 → 加载记录与草稿 → 回收未引用照片 → 开放编辑。操作意图损坏或存储读取失败时阻止继续写入，不把异常当作空数据。

导出的文件不用于内部事务。若目标存储写入失败，外部位置可能留下不完整文件，界面会明确告知导出未完成，请用户删除残件后重试；应用不会把该文件误报为成功备份。

## 文件与接口

- `storage/BackupCodec.ets`：版本1备份格式、引用完整性和路径校验。
- `storage/DataMaintenance.ets`：导出集合、合并策略、持久化操作意图和继续完成。
- `storage/BackupFiles.ets`：系统文件选择器、受限读取、处理短读／短写、SHA-256和新路径照片写入。
- `components/DataManager.ets`：导出、恢复预览、确认及删除入口。
- `pages/Index.ets`：启动恢复、操作互斥、状态刷新、失败后的编辑限制。

照片哈希用于发现损坏，不是来源认证；结构有效的备份内容仍由用户选择和确认。数据只通过用户选择的文件位置进出，不新增联网或同步服务。
