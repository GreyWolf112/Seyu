# 第5—6步：首页收敛与五个心事整理流程

## 首页

保留品牌、问候、快捷心情和一处插画。主要入口固定为“写下来”（图文/多情绪编辑器）、“理一理”（心事场景列表）、“歇一会儿”（放松页）。原书写模板移至心事页；插画场景仍在放松页可用。

存在未完成整理时显示“继续上次的心事整理”；有正式整理卡时展示最近一张的下一步或需要。该区域标为“最近留给自己的提醒”，不把最近记录冒充经过用户反馈验证的有效方法。方法反馈与统计属于后续步骤。

## 五个场景

- 有句话让我很在意：区分原话、事实与自己的理解。
- 我又勉强自己答应了：梳理顾虑、需要和可选回应。
- 和亲近的人有点难受：允许暂停、距离和寻求可信支持，不要求原谅或沟通。
- 今天真的有点撑不住：看见负担、支持需要和可暂缓事项。
- 我对自己有点苛刻：区分评价与事实，尝试更公平的表达。

每个场景共用4步引导：发生的事、最多3种感受、我的需要、下一步。场景提供不同问题和可编辑的提示。每一步允许跳过；跳过保留已经填写的内容，不自动生成答案。最后进入可编辑整理卡；全空的卡不保存为正式记录，选一种感受或写一句话即可保存。

## 暂存与正式记录

- 模型：`models/ReflectionModel.ets`。稳定场景id、场景内容、新建与更新函数。
- 界面：`components/ReflectionFlow.ets`，支持上一步、下一步、跳过、暂存离开、保留进度转去放松。
- 整理进度使用ReflectionResult可选字段step（0—3为问题，4为结果卡）。旧版无step的记录仍可读取。记录格式版本仍为1。
- 单独使用Preferences文件 `zhiyu_reflection_drafts`，复用有序草稿存储，不覆盖普通手记草稿。
- 首次进入、内容修改和步数变化均异步暂存；离开按钮等待落盘成功才退出。存在旧草稿时必须选择继续或明确舍弃。
- 整理卡以kind=reflection进入统一记录、日历、搜索和删除流程。重新编辑使用原id，保存后更新原卡。
- 正式记录成功但清理草稿失败时明确提示，重复保存不会新增另一张卡。
- 图片清理引用范围加入整理草稿，避免未来含图整理或已有记录的媒体被误删。

## 验证与边界

Debug HAP构建通过，35项主机逻辑测试通过（含五场景生成、进度恢复、草稿隔离、全跳过、正式卡重编辑不重复、非法进度及旧格式兼容）。未覆盖安装个人设备；真机仍需验证首页首屏、大字体、长提示换行、键盘、返回键和强杀后恢复。
